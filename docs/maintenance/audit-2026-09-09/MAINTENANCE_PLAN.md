# RAP-SLAM 维护计划

日期：2026-09-09。目标：先恢复可信、可追溯的研究状态，再决定研究方向。本文是待执行计划，本轮仅完成审查与接管底稿，未执行下列代码修复、数据备份或研究重跑。

关联材料：[当前状态](CURRENT_STATE.md)、[审查报告](AUDIT_REPORT.md)。F 编号对应审查报告。阶段按依赖排序，不用不可靠的工期估计代替验收条件。

## M0：保全成果，建立唯一实验登记表

优先级：立即。依赖：无。对应 F12、F17、F19。

- 固定两仓库提交、环境包清单、GPU/驱动、checkpoint 来源及 SHA256。确认论文、汇报、数据和产物分别由谁负责备份。
- 将不可再生或昂贵产物复制到独立归档位置：原始 accepted_loops、轨迹及源帧对应、摘要、运行日志、候选池、S1 特征与标签、训练/校准拆分、模型文件和矩阵缓存。大数据按可恢复性与下载成本分层，不要求把所有点云放进 Git。
- 归档后校验文件数量、大小、关键文件哈希，并实际读取一个归档样例。本次 manifest 只是部分小文件指纹，不能替代此步骤。
- 创建实验登记表：run_id、数据集/物理序列、帧区间/stride、输入与 GT 坐标系、源帧 ID、代码提交、配置、权重哈希、seed、候选预算、门控、NMS、PGO 权重、输出路径、状态、是否用于论文。历史不明字段标 unknown，不能推测补齐。
- 原始结果设为 legacy；修复版本写新目录并以 parent_run_id 关联，不覆盖旧输出。将 KITTI205 等配置名展开成明确参数，避免只靠会话简称解释。

验收：七组黄金产物可定位且已归档；从登记表能解释离线与 live 的差异；没有待归档产物仍处在会被验证脚本自动删除的唯一位置。

## M1：整理交接文档，冻结论文表述边界

优先级：立即，可与 M0 的整理工作交错。对应 F01、F12、F19。

- 将长 AGENTS 历史迁入按日期归档的记录，保留简短入口：目标、仓库职责、当前可信版本、启动命令、已知问题、下一步链接。历史结论保留原文并标注被哪个结论取代。
- 为 RAP-SLAM 建立当前状态与实验登记入口；RAP-main 对 SLAM 开发继续保持只读。确认 RAP-SLAM-report 是否需要独立版本管理和备份。
- 论文暂用“冻结预训练 RAP，无任务级微调”。追溯本地 checkpoint 与原论文训练配方；在确认具体训练/测试关系之前，不宣称 KITTI 或 Spires 为未见域。
- 区分系统目标、已经完成的实现、探索性实验和可支持的论文结论。暂停 S2–S5、新数据大规模运行与新增算法模块。

验收：新接手者从一个入口即可找到版本、数据、结果和待办；不再有多个相互冲突的“立即下一步”；零样本、召回率和误接受等关键表述均有明确统计对象与证据链接。

## M2：修复基础几何与评估协议

优先级：论文重算前必须完成。依赖：M0。对应 F02、F03、F10、F11、F16、F18。

1. 保护最终刚体拟合精度，明确 TF32 与 autocast 的边界；优先在 RAP-SLAM 适配层解决，确需改 RAP-main 时再单独界定上游补丁范围。验证正交性、det(R)、已知刚体回收与角度误差。阈值依据输入尺度和精度确定，不只检查输出 shape。
2. 修复 KITTI 子段统计：保存每段误差、有效段数量、长度、起止帧和速度。与官方评估实现用同一小样本逐段对照，明确相机/LiDAR 坐标及杆臂、端点和跨序列汇总规则；完成前指标命名为自定义评估，不能称完全官方一致。
3. 贯通 source_frame_id 与时间戳；GT 按真实选中 ID 取值，禁止用 min 长度静默截断。用缺帧、stride、乱序和时间戳不匹配样例验证失败行为。
4. Spires 在正式运行前验证 base→LiDAR 外参及首帧归一化，使用非零杆臂且有旋转的合成轨迹验证共轭关系。
5. 修复 crispness 跨观测最近邻查询，并保留观测标签；明确它与 Chamfer、独立 TLS 参考的区别。以报告中的反例验收。
6. 修复空回环 clique 路径，研究评测中让 KISS 初始化失败显式报错或明确选择备用后端。

验收：反例均有针对性回归；旧评估值与新协议值并列且可解释；抽取代表性 RAP 对重新推理，确认旋转合法性及指标影响，再决定必须重跑的实验范围。仅对旧旋转投影的诊断不得混入修复后实验表。

## M3：重建 S1 数据与统计证据链

优先级：S1 论文结论前必须完成。依赖：M0、M2。对应 F04–F09。

- 为每次配准建立唯一 measurement_id，绑定物理序列、帧对、生成次数/seed、选中的 T_rel、同次 overlap/mean_dist、GT 标签与特征版本。禁止跨 generation 拼指标，禁止按 pair 借用另一测量标签。
- 重建 SC margin，仅使用当时可见的历史候选，排除 self-match；保留检索时刻和候选集合的来源。
- 对输入数据逐项校验并导出质量报告：标签变更数、无法匹配数、重复物理 pair、旧版与新版特征差异。无足够 GT/变换的条目标未标注，不强行凑样本。
- 先确定分组拆分，再训练。至少隔离同一物理 pair；研究泛化评估按物理序列/地点分组，不能仅按 offline/live 数据集别名划分。fit、选择超参数、calibration、test 职责明确且保存 ID 清单。
- 部署 conformal 模型必须使用独立校准集；明确保证对象是条件危险样本的接受概率还是接受集合的污染率。不要用一个指标替代另一个，也不要把启发式 fallback 算入同一保证。
- 明确 σ 是标量误差预测界还是 SE(3) 切空间协方差。重新推导分布、分位数与覆盖口径，避免将三维误差范数直接解释为每轴高斯标准差。
- 报告保留等宽测试比较作为描述性诊断，标明 TEST 参与等宽化；实际部署性能另行计算。数据量不足则如实缩小结论，不预设 S1 必须获得正结果。

验收：任一表格数字可追溯到 measurement_id、split 与脚本；训练/测试组无规定范围内重叠；当前部署对象与被评估模型一致；重新发布 S1 结论和限制。原报告中的负结果保留为 legacy，不直接升级为普遍不可能性结论。

## M4：让运行可恢复、可重复

优先级：后续长跑前完成；ROS 项按论文是否依赖 live 展示排序。依赖：M0；核心修复不必等 ROS 全部完成。对应 F13–F18。

- 缓存键包含数据成员、预处理、点数预算、权重哈希、算法版本与随机种子；验证成员列表。每请求独立确定 RNG，比较冷缓存、全命中、部分命中三种运行。
- N-way 明确“只替换位姿”和“位姿与诊断一起替换”两种实验，避免旧诊断隐式驱动新边的 NMS/权重。统一或明确区分不同脚本的重新门控协议。
- 运行输出使用唯一 run_id；成功后原子更新 latest 指针。验证脚本不能默认删除前次结果；保存最终配置、阶段状态、实际后端、源帧清单和异常信息。
- live 客户端实现重连、EOF/损坏响应处理；worker 异常可见；退出时有明确 drain 状态、最终 PGO 和保存完成条件。用服务断开、超时、队列未清空和提前退出做故障注入，避免把节点仍活着当成闭环正常。
- 验证脚本分开报告帧完整性、数值合法性、基线回归与研究效果；长序列不再只靠绝对 10 m 阈值决定流程成败。
- 固化已验证的 conda 与 ROS 系统 Python 依赖边界；增加轻量自动检查和小型几何/评估回归。GPU 与 ROS 集成测试单独触发，不让基础 CI 依赖完整数据集。
- GPU 计时使用同步或 CUDA events；长序列缓存容量与本地 pickle 服务边界作为独立工程问题处理。

验收：一次失败不会覆盖已完成结果；失败原因和阶段可定位；同一请求在不同缓存状态下得到预期一致输出；无需靠旧会话回忆才能重跑。

## M5：建立论文可引用版本

优先级：恢复研究前的最后关口。依赖：M1–M3，以及该实验需要的 M4 条目。

- 创建 paper_v1 协议清单，与 legacy 分开。每个表格明确数据、帧范围、协议和统计汇总；不得按序列挑选表现最好的预算/NMS 后称作统一方法。
- 七组保存 PGO 的本轮精确复现作为“历史产物可复算”的证据；修复影响的 RAP 边、标签和指标按登记表重算，不能把它当成全链路已重新验证。
- 将系统工程贡献、RAP 继承能力、可验证的方法贡献分开陈述。N-way 同一批位姿导出的代数闭环成立，不等于检测了全局几何扭曲；需要独立约束支持相应结论。
- 统一 README、论文、图表与汇报中的数值，记录每个结论对应的代码提交与结果路径。引用文献中的指标注明来源与协议差异，不冒充本地复现基线。

验收：随机抽三条核心论文结论，均能从文字定位表格、产物、运行配置和评估脚本；未解决的限制有显式说明。完成这一关后，再由论文目标与剩余时间决定是否恢复 S2 或其他研究。

## 建议执行次序与边界

第一批：M0 保全 + M1 状态整理。第二批：M2 数值与评估。第三批：M3 S1 重建。第四批：M4 中影响后续运行的必需项 + M5 论文版本。

维护不承诺所有分数会上升。它的交付物是可信的结果和可解释的结论。可暂缓 GUI 美化、扩大数据下载、实时化、发布服务及新算法；若论文不使用 live 结果，ROS 韧性修复可以后置，但现有限制仍应记录。
