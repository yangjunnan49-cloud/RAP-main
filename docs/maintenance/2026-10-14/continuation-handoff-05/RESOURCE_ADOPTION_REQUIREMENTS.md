# Resource And Evidence Adoption Requirements

Late DESIGN_ONLY supplement. No integration is implemented or authorized by
this checklist. BEJ0/BPC0/WPC0/NMQ0 demonstrate precise tiny controls, not a
replacement supervisor or a remedy for old artifact/time/native failures.

## Declare The Boundary Before Launch

Name every payload/observer/helper process and distinguish ordinary preparation,
supervision/bookkeeping and scientific work. Give prospective time, CPU-memory,
GPU allocated/reserved and artifact bounds, with all attempts and retained
failures counted. Unknown setup observations remain unknown. A scope changing
its precision/function/storage contract is new work, not an amendment proving
an old run passed. Keep old source/freeze/failure/marker/seals immutable.

Use enclosing wall time once. Nested child wall intervals are already enclosed;
report them separately rather than summing twice. CPU time, wall time, sampled
host commit headroom, Linux ru_maxrss, Windows peak working set and peak commit
are different measures. Preserve their units/source/process identity; do not
label them interchangeable whole-system RSS or production latency.

## Complete Process And Native Statistics

Retain PID/session identity, exact frozen command, start/exit, native return,
resource source and every query error/missing observation. A successful parent
command does not prove all payloads exited successfully. A clean child exit does
not override incomplete outputs or failed logging. .NET no-exception/null is
not a numeric counter. Periodic snapshots cannot retrospectively fill a missed
final observation; empty catches must never support a zero-gap claim.

NMQ0 shows direct final OS peak queries worked with retained handles for3 new
fixed children. Any future use must retain/query the right handles, verify
return/field validity and preserve failures. Its observer complete lifetime
remains unknown. A future outer native observation arrangement needs its own
declared bookkeeping boundary and validation, not an infinite assertion that
self-snapshots cover all later work. Do not backfill old WPC0 or historical gaps.

Specify ownership and cleanup for every process and descendant before launch.
The current fixed fixtures create no descendants. In particular, inherited
pipe descriptors can outlive the immediate child; native exit must not disable
all drain/tree deadlines. Termination may target only the task's owned
process/session/job, never all python/wsl/powershell processes or unrelated work.
No process restart or production interruption follows from this document.

## Whole Cooperating Output Accounting

Inventory all payload, stream logs, manifests, source snapshots, failure files,
resource samples, terminal metadata, checksums and seals. Reserve their complete
framing/terminal bounds before writes. Any output bypassing the declared broker
or exclusive paths breaks a cooperating-writer claim. A post-hoc census detects
some violations but does not prevent an overrun or a race with another writer.

BEJ0 frames bytes within one file; BPC0/WPC0 add a separately reserved terminal
record. They do not intercept arbitrary NumPy/archive/third-party output paths.
An exclusive evidence.rdj filename is not a directory ACL or an OS storage quota.
External/hostile-writer guarantees need a different explicitly verified boundary.
Never describe the current prototypes as whole-dossier cap enforcement.

On overflow or partial I/O, retain evidence and fail admission; do not silently
truncate logs, refund failed allocations, delete prefixes or increase old caps.
Footer space does not guarantee successful footer I/O or crash durability.
Missing expected files, malformed/torn records, failed native exit, invalid
terminal metadata or unresolved output identities must deny completion.

## Admission And Future Scope

Admission is a conjunction of the complete expected population, valid payloads,
independent reconstruction/metrics when applicable, native exit/lifecycle,
resource gate and namespace integrity. Journal status alone is insufficient;
empty synthetic success is not a scientific bank. Exit0 on overflowing fixtures
is specifically a negative control, not a passing evidence job.

Adopt only after a separately justified task needs this infrastructure and its
full fixed-output/lifecycle contract is frozen. Include launch failure, terminal
I/O failure, descendant-held pipes and complete resource ownership when relevant;
the current fixed8/15-case controls cannot silently expand to those claims.
No old HFIT0/LCP0 retry, packing reconstruction, full-noise conclusion, old cap
repair, deployment or new scientific result is authorized by this checklist.
