# System metric opportunity audit — prospective protocol

Status: **design frozen only when `freeze.json` exists**. This is an evaluator-only diagnostic of saved E0 arm A, not a method, a new RAP inference run, or independent confirmation. The owner authorized this direction on 2026-09-29. No existing E0 bank may be modified.

## Question and fixed cohort

Which existing source of error offers the most credible opportunity to improve full-system KITTI translation drift (`ter`) and aligned LiDAR ATE: local odometry, current accepted loop transforms, or online candidate exposure? Use 00/05/06 observed development and 07/09/10 earlier engineering transfer. All six are now diagnostic/exposed for this research choice. Preserve both metrics and report per sequence and cohort; never optimize one by silently trading away the other.

The frozen inputs are `odom_poses.txt`, `optimized_poses.txt`, `keyframes.json`, `accepted_loops.json`, `source_frames.json`, `verification_measurements.jsonl`, `summary.json`, the six KITTI GT pose and calibration files, `rap_slam/pose_graph.py`, `rap_slam/real_dataset.py`, `rap_slam/trajectory_protocol.py`, `scripts/eval_paper_metrics.py`, this protocol, runner, and separate validator. Freeze SHA-256 and package versions before new case-level output. Existing E0 E1 baseline reports provide provenance but are not rewritten.

## Stage A: GT-free bank

Read each saved loop through the allowlist `i,j,T_rel,overlap,mean_dist,measurement_id`; discard embedded GT/evaluator fields. Parse online `candidate_started`, `generation`, and `candidate_finished` records, omitting their `labels` and any evaluator fields. Assert IDs 0..N-1, keyframe membership, count reconciliation, accepted measurement identity, finite SE(3), and one finished record per start. E0 A has 71 attempted candidates and 58 accepted edges by preflight inventory; any mismatch stops execution.

Replay the unchanged pose graph from the saved odometry, keyframes and accepted loops using `pose_graph.optimize_pose_graph` defaults and `propagate_to_full_trajectory`. Require maximum absolute pose-entry difference from saved `optimized_poses.txt` <=1e-5. Re-optimize once per accepted edge with **only that edge omitted**; retain all other endpoints, transforms and weights. Save the complete GT-free trajectories and candidate status ledger into a new append-only attempt directory. Hash every bank file and save `bank_seal.json` before Stage B reads GT. An `INCOMPLETE` marker remains until independent validation passes. Do not overwrite an existing attempt. No GPU, scan processing, checkpoint load, or algorithm change.

## Stage B: evaluator-only diagnostics

Load KITTI GT with `load_gt_poses(..., apply_calib=True)` and calibration `Tr`, using the same E0/E1 convention. For each odometry and saved/replayed full trajectory, calculate aligned LiDAR ATE and KITTI camera-frame `ter/rer` via the existing `eval_paper_metrics.evaluate_pair`. Save every official `kitti_segment_record` for odometry and full with source start/end, 100..800m length, errors, and signed full-minus-odom differences. Report arithmetic per-sequence and per-cohort means; no pooled-segment headline. Describe concentration as the share of the sum of odometry segment translation errors carried by the worst 10% of segments, with overlapping segments explicitly acknowledged. Relate interval locations to loop endpoints descriptively only.

For every leave-one-edge-out bank trajectory, evaluate the same ter/rer/ATE. Define contribution as **baseline full minus omitted-edge result** (negative means the included edge improves an error metric). Graph interactions make these nonadditive and not causal shares. No selection or refit based on GT.

For each already accepted edge only, create a separate evaluator-only replay replacing exactly its measured `T_rel` with `inv(GT[i]) @ GT[j]`, holding endpoints, all other edges, odometry and graph settings fixed. Measure its pair pose discrepancy independently and require the oracle relative transform error <1e-6 (matrix entries). This is a one-at-a-time same-endpoint diagnostic, not a general ceiling or deployable algorithm. Do not search/add GT pairs. Save oracle trajectories only if needed for independent validation; never place them in the Stage A bank.

For online exposure, use only attempted candidate endpoint pairs. Match each `candidate_finished.selected_measurement_id` to its generation, independently recompute GT endpoint place distance and selected pose translation/rotation errors, and tabulate attempted/accepted/rejected, near place pairs (GT distance <= the saved `loop_dist`), strict pose accuracy (<1m and <5deg), and sequence 10 separately. Near place is opportunity context, not a graph-useful loop label. The log has no complete pre-verification retrieval shortlist: **do not claim to measure retrieval recall or all missed revisits**. An optional GT query-keyframe proximity census must be explicitly labeled evaluator-only and cannot be used to select a new algorithm here.

Compare same-data KISS-SLAM local motion only where exact frame alignment and calibration can be verified. If raw same-data products are missing, quote the frozen E0 comparison and mark this subanalysis unavailable; do not silently mix configurations. F2 balanced K4 pairs are not the online E0 K1/4000-point distribution.

Decision is an opportunity **ranking with uncertainty**, not a pass/fail method claim. Report the two metric axes, leave-one-out and oracle distributions, online attempted exposure, and local-motion comparator separately. A loop branch requires material same-endpoint oracle movement on trajectory metrics without unacceptable ter regression; an odometry branch requires an observed local-motion gap at matching frames.
