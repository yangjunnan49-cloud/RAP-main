# Lossless storage prerequisite — DESIGN_ONLY

The failed pilot stores full3000x512 float32 prefixes at every step. One prefix is6,144,000 raw bytes;51 five-step traces contain255 prefixes,1,566,720,000 raw prefix bytes before compression, plus roughly1.05GB(decimal) observed in the dossier before prediction. Ordinary compressed NPZ is insufficient under the original2GiB aggregate scope. These arithmetic requirements explain the storage boundary; they do not permit changing the cap or deleting already required evidence.

Candidate prospective representation: retain full U prefix per noise/time, bind every unchanged first-step prefix by SHA, and encode other paired prefixes as lossless uint32 XOR deltas against U at identical noise/time. This preserves every float32 bit, including signs/NaN encodings if any; numerical validity still separately requires finite arrays. Use shape/dtype/byte-order/source-sha/base-sha/delta-sha/reconstructed-sha manifests. Reconstruct bytes via a separately implemented byte-view decoder and compare original array bytes/hashes. Never use lossy quantization, selected rows or a replacement numerical gate to rescue the existing study.

Compression ratio on available data cannot guarantee all missing P traces or whole future corpus fits; separate conservative budget accounting must include all remaining metadata/fit/replay/source buffers.
